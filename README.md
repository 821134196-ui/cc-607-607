# 剧场无障碍字幕设备预约与归还系统

为需要字幕辅助的观众提供**按场次、按语言**的无障碍设备预约；前台与技术员共同保证**发出的设备**与**字幕内容**都适合当场演出。

技术栈：PHP 8.2 · Laravel 11 · React 18 · Eloquent · SQLite · Vite。票务与通知接口为**本地模拟**。

## 一条命令启动

```bash
./dev.sh           # 首次会自动装依赖、迁移、播种，然后同时启动前后端
./dev.sh --reset   # 重置数据库并重新播种
```

| 入口 | 地址 |
| --- | --- |
| 观众预约（大字高对比） | http://127.0.0.1:5173/ |
| 预约查询/改签/取消 | http://127.0.0.1:5173/reservations/凭证号 |
| 前台工作台（发放/回收复检） | http://127.0.0.1:5173/frontdesk |
| 技术员·字幕版本 | http://127.0.0.1:5173/technician |
| 负责人·换稿审批 | http://127.0.0.1:5173/approvals |
| 后台总览（占用/检查/通知） | http://127.0.0.1:5173/admin |

后端 API 文档即路由表：`backend/routes/api.php`。

> 员工页面首次进入需选择当前身份（前台/技术员/负责人）。这是演示用的轻量身份切换（请求头 `X-Staff-User-Id`），真实部署应替换为登录会话。

## 业务流程与规则

```
观众预约                    前台                        技术员              负责人
场次+语言→看余量             凭证查询                     发布字幕版本          审批演出中换稿
预约(占配额) ──────────────► 核对编号/电量/语言 ──► 设备发放
改签=先释放旧预约再建新预约                                  （字幕必须对应场次）
取消=立即释放配额             散场收回+复检 ──► 合格:可再分配 / 故障:锁定       演出中换稿:申请→批准→切换
```

1. **预约与改签**
   - 每场次 × 每语言有配额；观众选择场次、语言后实时看到「可预约 N 台」。
   - 预约在数据库写事务内检查容量（SQLite 写事务串行化），不会超额。
   - **改签在同一事务内先把原预约置为 `released`（释放占用），再建立新预约**；新场次已满时整个回滚，旧预约保持有效。已发放设备的预约不能在线改签。
2. **设备发放（前台）**：必须核对①实物编号对应设备、②电量（默认 ≥20%）、③设备字幕语言与预约一致；故障设备、有未归还记录的设备不能发放。
3. **散场复检**：归还时再次检查；**未归还或复检故障的设备不能分配给下一场**（故障设备锁定，需维修登记恢复）。
4. **设备防重复分配**：`device_assignments` 上建有部分唯一索引
   `UNIQUE(device_id) WHERE returned_at IS NULL`，数据库层兜底，任何路径都无法把同一台设备发给两个人。
5. **字幕版本**：技术员发布时必须选定场次与语言；每个版本独立落盘
   （`storage/app/private/subtitles/screening-<id>/<lang>/v<n>-<hash>.srt`），**旧文件永不覆盖、永不删除**，版本历史可查、可看内容。
6. **演出中换稿**：演出开始后发布的新版本只保存、不自动生效；技术员发起申请 → **负责人批准后**才切换当前稿，系统记录实际切换时间；驳回则继续用原稿。
7. **无障碍**：观众端大字（19px 基准）、深色底高对比配色、4px 粗焦点框、跳转链接、原生 radio/checkbox/button，**Tab + 方向键 + Enter/Space 可走完全部预约流程**。

## 模拟接口

- **票务**：`App\Services\TicketService` —— 校验票号是否存在、属于该场次、未退未用（数据在 `tickets` 表，如 `T001-S1`）。
- **通知**：`App\Services\NotificationService` —— 预约成功写短信记录，可在「后台总览 → 模拟通知记录」查看。

## 自动化验证

```bash
cd backend && php artisan test --filter=BusinessRules
```

覆盖三条关键规则：改签释放旧占用、设备不可重复分配（故障/未归还不可再分配）、演出中换稿必须批准且历史版本可查。
